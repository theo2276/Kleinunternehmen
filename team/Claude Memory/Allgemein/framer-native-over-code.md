For the Framer templates (see [[framer-template-business]]), reach for native Framer effects before writing a code component.

Native equivalents that replace things worth mistaking for custom code: `appearEffect` (scroll reveal — onInView, threshold, enter y/opacity/scale, spring transition, stagger), `tickerEffect` (marquee — velocity, hover modifier, direction, draggable), `styleTransformEffect` and `textEffect` (scroll-driven and per-character text motion), `customCursor.*`, project shaders (mesh, liquid-gradient, particles, fluted-glass), and variants for tabs, accordions and pricing toggles. A counting-number animation is a real code case; most others are not.

**Why:** Framer's own docs say to prefer a code override over a code component, and the Marketplace requirements explicitly ask creators to minimize custom code and prioritize native features — so a template that reimplements marquees or reveals in React loses at review and is harder to maintain.

**How to apply:** Before building any motion or interaction as code, check the DSL attribute list in the generated project prompt for a native effect that covers it. Write code only for logic with no native counterpart.

Canvas constraints learned the hard way: `hoverEffect`, `tapEffect` and `scale` are all rejected on a component variant root or page breakpoint — use Gesture Variants (`CREATE_VARIANT … gesture="hover"|"pressed"`) and express pressed feedback as a fill shift. `minWidth` cannot be set on a text style's `default` breakpoint slot; it is derived from the first replica. DSL comments must be `/** */` — a plain `/* */` swallows the commands that follow it.

Variant-override ordering matters: setting an attribute on the PRIMARY variant wipes the same attribute's overrides on replica variants, so apply primary-variant changes first and replica overrides last. Replica descendants are addressed by a compound id (`<variantId><nodeId>`), but the primary variant's descendants use their plain id — a compound id built from the primary variant id does not resolve. `onTap` cannot go on an IconNode; wrap it in a FrameNode. A `+FrameNode` created as a ComponentNode's primary variant cannot be targeted by a `SET` in the same applyChanges call — style it in a follow-up call. And a single `SET` is all-or-nothing: one invalid attribute discards every other attribute in that command, which silently leaves nodes at their defaults.

Array variables: `repeat.variable` over an ArrayVariable renders correctly and the array's DEFAULT values can be set on the component, but an array whose items have named fields reports as item type "object" and CANNOT be set per instance through the DSL — so every instance shows the same list. For per-instance lists, use individual string variables instead. Also, setting a string control to "" does not clear it; the instance falls back to the variable's initial value, so write a real replacement string.

Layout templates: breakpoints require a fixed pixel height (not `auto`), only support vertical stacks, and own the page's fill, padding, alignment, overflow and base font size — those stop being settable on the page breakpoint. A PlaceholderNode is created automatically; shared chrome goes around it. MOVE works for relocating existing page nodes into the template.

CMS ordering rule: configure the parent as a Collection List (`collectionList.collection` + `repeatedDescendantId`) BEFORE setting anything on the repeated card. Until the list exists, the collection's variables are not in scope and every CMS binding on the card is rejected — the cards then render field-name placeholders rather than failing loudly. `aspectRatio` also needs a non-auto height. After creating a breakpoint replica, `getRect` (and an immediate screenshot) can report the SOURCE width rather than the one just set — the reading settles once the page's full set of breakpoints exists. Re-measure before concluding a breakpoint is broken; deleting and recreating it is usually unnecessary.

Forms: a form's submit button must be its own component whose variants all carry `htmlTag="button"` and which provides Pending/Success/Error variants — a general-purpose link button is rejected with "form submit button ComponentNode needs htmlTag button on all variants". Wire it in this order: `formSubmitButtonId` on the form FIRST, then `formButtonPendingVariant`/`SuccessVariant`/`ErrorVariant` on the instance, which are refused until the instance is recognised as the submit button. Temporary DSL ids stay claimed for the whole session, so reusing one across calls collides — give each call fresh ids. Percentage and fraction widths are rejected on variant-root and ground nodes.

A RichTextNode's heading level comes from its text style preset — setting `tag` alongside `textStylePreset` is silently ignored. To change semantics without changing the look, add a preset with the right tag and the same visual values (that is why Kernel has a "Card Title" preset: h3 at Heading 4's size). `SET name` on a WebPageNode is also ignored; Framer derives a page's display name from its path, with Home as the exception. Audit scripts must flatten array-valued attributes — `boxShadows` is an array, so a string-only scan misses hardcoded shadow colors entirely.

Scroll motion beyond `appearEffect` is all native too: `textEffect` (per character/word/line, with blur), `parallaxEffect.speed`, `styleTransformEffect` (scroll-linked opacity/scale/position), `scrollVariantEffect` and `tickerEffect`. Framer rewrites a `spring-physics` transition on a textEffect into `spring-duration` and appends the per-token stagger to the delay slot, so read the value back rather than assuming it stuck. Parallax on a child of a clipped parent pushes it out of the clip and the linter flags it — keep parallax on unclipped containers. A ticker always trips that same clipping warning by design, since a marquee overflows its parent on purpose.

Animation cannot be verified from screenshots — values can be read back, but the motion itself has to be checked in a live preview by the user.

Kernel "extravagant motion" build (2026-09-19), Global + Home only (scoped by user request):
- Absolute positioning on a ComponentInstanceNode needs position+left+top all in ONE successful applyChanges call. If an earlier call partially fails (e.g. rejects percentage left/top), the node silently keeps default position:"relative" and later calls that only set left/top (without re-asserting position="absolute") are accepted but inert — always re-check getRect after any absolute-position SET, never trust "applied cleanly" alone for positioning.
- ControlType.Array with an Object sub-control cannot be set via the DSL's `$control__x.<i>.<field>` addressing ("unsupported array item type 'object'") — only primitive array items work that way. Ship a sensible default array in the component instead and don't try to override it from exec.
- A code override's export is only classified as `type:"override"` by Framer's own static analysis of its signature; my `(Component) => (props) => ...` HOC was classified as a plain `type:"component"` instead, meaning `codeOverride="..."` would likely reject it. Never used it — do not assume a hand-written override shape is auto-detected; verify the compiled export's `type` before wiring it in.
- Computer-use screen testing: hover-triggered CSS (:hover, native hoverEffect included) could not be triggered via synthetic mouse_move across three different Framer preview surfaces (embedded canvas preview, per-breakpoint mini preview, full "Show UI" preview) — likely an Electron/Chromium synthetic-input limitation, not a build defect, since even a known-working native hoverEffect failed to visually react the same way. Scroll-based and click-based effects (page transitions, continuous marquee) verified genuinely live and worked correctly, including one real mid-transition captured frame proving the pageEffects.all crossfade.
- New code components this round: KernelButtonSheen (hover/focus sweep via parentElement listeners, pointer-events:none, safe), KernelMetalSurface ("core"/"lens404" chrome shape with idle conic drift), KernelSignalPaths (SVG converging lines + staggered pulses, decorative/schematic), KernelSlicedType (real accessible text at opacity 0 + N aria-hidden clipped strips converging in — used to replace AnimatedCounter on the stat band per this round's brief). A planned KernelApertureOverride (scroll-driven clip-path reveal for the CTA) was built but abandoned after compiling as a plain component rather than an override; the CTA instead keeps its already-verified native styleTransformEffect (strengthened) plus a native radial-gradient vignette frame — logged as an explicit scope reduction.

**Nachtrag 16.10.2026 (Kreuzberg on KulTour):** Framer kann CMS-Listen nicht von selbst nach „ab heute“ filtern. Ein Filterwert „now“ wird zwar angenommen, wirkt aber nicht nachweislich. Lösung: die Liste in ein Bauteil legen, dort eine Datumsvariable „Heute“ anlegen, den Filter „Datum ist nach Heute“ setzen und auf die Bauteil-Instanz einen Code-Override legen, der `heute={new Date().toISOString()}` übergibt. Der Filter wirkt nur in Vorschau und live, nicht im Canvas. Die Kennung eines Overrides für `codeOverride` lautet `codeFile/<Datei-ID>:<Exportname>`. `listComponents` zeigt neue Overrides manchmal nicht an, die Schreibweise funktioniert trotzdem. Siehe [[project-kreuzberg-on-kultour-website]].
